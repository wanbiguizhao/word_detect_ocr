# 多轮聚类标注页面 - 需求规格说明书

## 1. 页面概述

| 属性 | 值 |
|------|-----|
| **路由** | `/mc-label/:round/:cluster_id` |
| **用途** | 对聚类结果中的字符进行标注、跳过、撤回操作 |

| **后端接口** | `/api/mc/rounds/:round/clusters/:cluster_id` |

## 8. 标注操作

### 8.1 单个标注

- 在输入框中输入汉字
- 失焦（blur）时自动保存
- 接口：`POST /api/mc/rounds/:round/clusters/:cluster_id/labels`
- 请求体：`{ charIndex, char }`

### 8.2 批量标注

- 在工具栏输入框输入汉字
- 点击"保存全部 (N)"批量标注选中项
- 接口：`POST /api/mc/rounds/:round/clusters/:cluster_id/labels/batch`
- 请求体：`{ labels: [{ charIndex, char }] }`
- 保存后自动刷新数据

### 8.3 跳过整个聚类

- 点击"暂不标记"按钮
- 确认后跳过聚类中所有字符
- 接口：`POST /api/mc/rounds/:round/clusters/:cluster_id/skip`
- 操作后返回列表页

---

## 9. 跳过与撤回操作

### 9.1 单个跳过

- 悬停图片右上角显示红色"跳过"按钮
- 接口：`POST /api/mc/rounds/:round/chars/:char_id/skip`
- 跳过后卡片显示灰色半透明 + "已跳过"标签

### 9.2 单个撤回

- 已跳过图片悬停显示绿色"撤回"按钮
- 接口：`POST /api/mc/rounds/:round/chars/:char_id/unskip`
- 撤回后恢复为可标注状态

### 9.3 批量跳过

- 选中多个图片后点击"批量跳过 (N)"
- 接口：`POST /api/mc/rounds/:round/chars/batch-skip`
- 请求体：`{ char_ids: [...] }`
- 批量操作，单次请求，避免并发冲突

### 9.4 批量撤回

- 选中多个已跳过图片后点击"批量撤回 (N)"
- 接口：`POST /api/mc/rounds/:round/chars/batch-unskip`
- 请求体：`{ char_ids: [...] }`

## 11. 排序逻辑

排序优先级（从高到低）：

1. **标注状态**：未标注优先于已标注
2. **标注数量**：按标注汉字的出现次数升序
3. **字母序**：同数量时按汉字字母序

### 选中项排序

- 选中项排到前面，未选中项排到后面

## 14. 数据一致性

### 14.1 标注操作同步范围

| 操作 | char_pool | round_labels.json | pre_labels.json | prelabel_status.json | unified_labels.json |
|------|-----------|-------------------|-----------------|---------------------|---------------------|
| 标注字符 | mark_as_labeled + labeled.json 添加 | 更新 char_labels | status → confirmed | status → confirmed | char + status 更新 |
| 跳过字符 | mark_as_skipped + labeled.json 移除 | char_labels → skipped | status → skipped | status → skipped | status → skipped |
| 撤回跳过 | reset_char + labeled.json 移除 | 删除 char_labels, cluster → unlabeled | status → pending | status → pending | status → pending |
| 跳过聚类 | 批量 mark_as_skipped + labeled.json 移除 | status → skipped | 批量 skipped | 批量 skipped | 批量 skipped |

> **标注覆盖**：同一字符允许修改已有标签（覆盖模式）。`_validate_update` 不再阻止标签变更，而是记录覆盖日志。

### 14.2 跨轮次同步机制

> **重要**：同一字符可能存在于多个轮次的聚类中。当从预标注页面或其他聚类页面触发同步时，同步方法必须遍历所有轮次，确保每个包含该字符的聚类标注都被更新。

| 同步方法 | 功能 | 遍历行为 |
|----------|------|----------|
| `_sync_to_multi_clustering()` | 同步标注到多轮聚类 | 遍历所有 `round_N/` 目录，更新包含该 `char_id` 的聚类 |
| `_sync_skip_to_multi_clustering()` | 同步跳过到多轮聚类 | 同上 |
| `_sync_reset_to_multi_clustering()` | 同步重置到多轮聚类 | 同上 |

文件写入优化：每个轮次仅在有变更时保存一次 `labels.json`，避免重复 I/O。

### 14.3 批量操作优化

| 操作 | 优化方式 |
|------|----------|
| 批量跳过 | `batch_mark_as_skipped` + `batch_skip_prelabels`，单次文件IO |
| 批量撤回 | 单次请求批量处理 |
| 批量标注 | 逐个 `write_annotation`（后续可优化为 `batch_write_annotations`） |

### 14.4 历史问题与修复

| 问题 | 根因 | 修复 |
|------|------|------|
| 预标注确认后，多轮聚类页面无汉字显示 | `_sync_to_multi_clustering` 找到第一个匹配后 `return`，未继续更新其他轮次 | 改为遍历所有轮次，用 `round_found` 标记，每轮结束后统一保存 |
| 写入路径错误 | 使用 `round_dir / "labeling" / "labels.json"` 而非 `round_dir / "labels.json"` | 修正为 `round_dir / "labels.json"` |
| 数据结构错误 | 直接操作 `labels` 顶层字典，但文件结构为 `{"labels": {cluster_id: {...}}}` | 改为 `labels_data["labels"]` 操作后保存 `labels_data` |
| 已有标签无法修改 | `_validate_update` 在字符已有标签且新标签不同时 `raise ValueError` | 改为覆盖模式，`_validate_update` 始终返回 `True`，记录覆盖日志 |
| 跳过操作双重同步 | Manager 的 `_sync_skip_to_all` 调用 `batch_skip_prelabels`，后者内部已同步 `unified_labels`、`char_pool`、`multi_clustering`，Manager 又额外调用 `_update_unified_labels_status` | 给 `batch_skip_prelabels` 添加 `sync_downstream` 参数，Manager 调用时设为 `False`，由 Manager 统一调度同步 |
| 跳过操作缺少 round labels 同步 | `_sync_skip_to_all` 未显式同步 `round_N/labels.json` | 新增步骤 5：调用 `_sync_skip_to_multi_clustering` 显式同步多轮聚类 |
| 撤回跳过缺少 round labels 同步 | `_sync_unskip_to_all` 未同步 `round_N/labels.json` | 新增步骤 5：调用 `_sync_reset_to_multi_clustering` 显式同步多轮聚类 |
| 跳过后 labeled.json 未清理 | `_sync_to_char_pool_skipped` 和 `CharPoolManager.mark_as_skipped` 未从 `labeled.json` 移除 | 两个方法均新增从 `labeled.json` 移除的逻辑 |
| revoke_annotation 调用空方法 | `_remove_from_multi_clustering` 是空方法，与 `_sync_reset_to_multi_clustering` 功能重叠 | 删除空方法调用，保留已实现的 `_sync_reset_to_multi_clustering` |

## 15. OCR 数据显示

### 15.1 数据来源

后端 `get_cluster_detail` 接口通过 `data_store.get_prelabel_by_char_id(char_id)` 获取 OCR 数据。

### 15.2 返回字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `predicted_char` | string | OCR 预测的汉字 |
| `confidence` | float | 置信度 (0-1) |
| `confidence_level` | string | 置信度等级 (high/medium/low) |

### 15.3 显示规则

- 有 OCR 数据时：左上角显示预测字符（蓝色超链接）+ 置信度百分比
- 无 OCR 数据时：不显示
- 点击预测字符：新标签页打开 `/prelabel-confirm/{predicted_char}`
