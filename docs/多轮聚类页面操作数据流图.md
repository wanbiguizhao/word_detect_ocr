# 多轮聚类页面操作数据流图

## 1. 概述

本文档描述同一张图片在**多轮聚类标注页面**（`/mc-label/:round/:cluster_id`）执行操作后，数据在各系统间的流转情况，以及**预标注确认页面**（`/prelabel-confirm/:char`）看到的数据变化。

---

## 2. 涉及的数据存储

| 存储文件 | 路径 | 说明 |
|----------|------|------|
| pre_labels.json | `bussiness/datahome/{dataset}/pre_labels.json` | OCR 预测结果（predicted_char, confidence） |
| prelabel_status.json | `bussiness/datahome/{dataset}/prelabel_status.json` | 预标注状态（status, corrected_chars） |
| unified_labels.json | `bussiness/datahome/{dataset}/unified_labels.json` | 统一标注数据（char, status, source） |
| all_chars.json | `bussiness/datahome/{dataset}/multi_clustering/char_pool/all_chars.json` | 字符池（status, label, labeled_round） |
| unlabeled.json | `bussiness/datahome/{dataset}/multi_clustering/char_pool/unlabeled.json` | 未标注字符列表 |
| labeled.json | `bussiness/datahome/{dataset}/multi_clustering/char_pool/labeled.json` | 已标注字符列表 |
| round labels.json | `bussiness/datahome/{dataset}/multi_clustering/rounds/round_N/labels.json` | 多轮聚类标注（char_labels, status） |
| label_history.json | `bussiness/datahome/{dataset}/label_history.json` | 标注历史记录 |

---

## 3. 初始状态

假设图片 `page_1_line_3_char_5`，OCR 预测为"效"，置信度 0.85，位于第 2 轮聚类 45 号：

```
pre_labels.json:
  page_1_line_3_char_5 → { predicted_char: "效", confidence: 0.85 }

prelabel_status.json:
  status: { page_1_line_3_char_5: "pending" }
  corrected_chars: {}

unified_labels.json:
  annotations: []

all_chars.json:
  page_1_line_3_char_5 → { status: "unlabeled", label: null }

unlabeled.json:
  char_ids: ["page_1_line_3_char_5", ...]

labeled.json:
  char_ids: []

round_2/labels.json:
  labels: { "45": { status: "unlabeled", char_labels: {} } }
```

## 4. 操作一：标注字符（Label）

### 4.1 触发方式

- 输入框失焦自动保存（`POST /api/mc/rounds/:round/clusters/:cluster_id/labels`）
- 批量标注（`POST /api/mc/rounds/:round/clusters/:cluster_id/labels/batch`）

### 4.2 调用链

```
前端 → POST /api/mc/rounds/:round/clusters/:cluster_id/labels
     → MultiClusteringManager.save_label(round_num, cluster_id, charIndex, char)
```

### 4.3 数据流图

```
┌─────────────────────────────────────────────────────────────────────────┐
│                  多轮聚类页面 - 标注操作                                 │
│                                                                         │
│  用户输入 "敦" → char_id="page_1_line_3_char_5", char="敦"             │
│  （若已有标签，覆盖模式：旧标签 → 新标签）                               │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  MultiClusteringManager.save_label()                                     │
│                                                                          │
│  ① round_N/labels.json (本地保存)                                        │
│     labels: { "45": {                                                    │
│       char_labels: { "0": { char: "敦", labeled_at: "..." } },          │
│       char: "敦", status: "labeled", confidence: 1.0                    │
│     }}                                                                   │
│                                                                          │
│  ② CharPool.mark_as_labeled(char_id, "敦", round_num)                   │
│     all_chars.json:                                                      │
│       page_1_line_3_char_5 → { status: "labeled", label: "敦" }         │
│     unlabeled.json:                                                      │
│       从列表中移除 page_1_line_3_char_5                                  │
│     labeled.json:                                                        │
│       添加 page_1_line_3_char_5                                          │
│                                                                          │
│  ③ DataStore.write_annotation(char_id, "敦")                             │
│     ├── _validate_update(): 覆盖模式，允许修改已有标签                    │
│     ├── unified_labels.json:                                             │
│     │   annotations: [                                                   │
│     │     { char_id: "page_1_line_3_char_5", char: "敦",                 │
│     │       status: "labeled", source: "manual" }                        │
│     │   ]                                                                │
│     ├── label_history.json:                                              │
│     │   history: [{ char_id: "page_1_line_3_char_5",                     │
│     │     old_char: null, new_char: "敦", source: "manual" }]           │
│     ├── _sync_to_cluster_labels():                                       │
│     │   clusters/labeling/labels.json 更新                               │
│     ├── batch_confirm_prelabels():                                       │
│     │   prelabel_status.json: status → "confirmed"                       │
│     ├── correct_prelabel_char():                                         │
│     │   prelabel_status.json: corrected_chars → { "敦" }  ✅ 已修复     │
│     ├── _sync_to_char_pool_labeled():                                    │
│     │   all_chars.json: status → "labeled", labeled_char → "敦"         │
│     │   unlabeled.json: 移除 page_1_line_3_char_5                        │
│     │   labeled.json: 添加 page_1_line_3_char_5                          │
│     └── _sync_to_multi_clustering():                                     │
│         遍历其他轮次的 labels.json 同步更新                               │
│         同一字符可能存在于多个轮次，全部更新                               │
└──────────────────────────────────────────────────────────────────────────┘
```

## 5. 操作二：跳过字符（Skip）

### 5.1 触发方式

- 单个跳过按钮（`POST /api/mc/rounds/:round/chars/:char_id/skip`）

- 跳过整个聚类（`POST /api/mc/rounds/:round/clusters/:cluster_id/skip`）

### 5.2 调用链

```
前端 → POST /api/mc/rounds/:round/chars/:char_id/skip
     → MultiClusteringManager.skip_char(char_id, round_num)
     → _sync_skip_to_all([char_id], round_num)
```

└──────────────────────────────┬──────────────────────────────────────────┘

                               ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  MultiClusteringManager._sync_skip_to_all()                              │
│                                                                          │
│  ① CharPool.batch_mark_as_skipped([char_id], round_num)                 │

│       page_1_line_3_char_5 → { status: "skipped", labeled_round: 2 }    │
│     unlabeled.json:                                                      │

## 8. 数据一致性总结

### 8.1 操作同步矩阵

| 操作 | round labels | all_chars | unlabeled.json | labeled.json | prelabel_status | unified_labels | pre_labels |
|------|-------------|-----------|----------------|--------------|-----------------|----------------|------------|
| 标注字符 | ✅ labeled | ✅ labeled | ✅ 移除 | ✅ 添加 | ✅ confirmed + corrected | ✅ labeled | - |
| 跳过字符 | ✅ skipped | ✅ skipped | ✅ 移除 | ✅ 移除 | ✅ skipped | ✅ skipped | ✅ skipped |
| 撤回跳过 | ✅ 删除char_labels | ✅ unlabeled | ✅ 添加 | ✅ 移除 | ✅ pending | ✅ pending | ✅ pending |
| 跳过聚类 | ✅ skipped | ✅ skipped | ✅ 移除 | ✅ 移除 | ✅ skipped | ✅ skipped | ✅ skipped |

> **标注覆盖**：同一字符允许修改已有标签（覆盖模式）。`_validate_update` 不再阻止标签变更，而是记录覆盖日志。

### 8.2 双向一致性对比

| 方向 | 同步完整性 | 说明 |
|------|-----------|------|
| 多轮聚类 → 预标注 | ✅ 完整 | 标注/跳过/撤回均全系统同步 |
| 预标注 → 多轮聚类 | ✅ 完整 | 确认/修改/跳过/撤回均全系统同步 |

### 8.3 关键同步方法

| 方法 | 功能 | 调用位置 |
|------|------|----------|
| `correct_prelabel_char()` | 更新 corrected_chars 字段 | `write_annotation()`（聚类标注时） |
| `_sync_to_char_pool_labeled()` | 同步标注到字符池（all_chars + labeled + unlabeled） | `write_annotation()`、`batch_write_annotations()` |
| `_sync_to_char_pool_skipped()` | 同步跳过到字符池（all_chars + unlabeled + labeled移除） | `skip_prelabel()`、`batch_skip_prelabels()` |
| `_sync_to_char_pool_reset()` | 同步重置到字符池（all_chars + unlabeled + labeled移除） | `revoke_annotation()`、`unskip_prelabel()` |
| `_sync_to_multi_clustering()` | 同步标注到多轮聚类（**遍历所有轮次**） | `write_annotation()`、`batch_write_annotations()` |
| `_sync_skip_to_multi_clustering()` | 同步跳过到多轮聚类（**遍历所有轮次**） | `skip_prelabel()`、`batch_skip_prelabels()`、`_sync_skip_to_all()` |
| `_sync_reset_to_multi_clustering()` | 同步重置到多轮聚类（**遍历所有轮次**） | `revoke_annotation()`、`unskip_prelabel()`、`_sync_unskip_to_all()` |
| `_sync_skip_to_all()` | 聚类跳过全系统同步 | `MultiClusteringManager.skip_char()`、`skip_cluster()` |
| `_sync_unskip_to_all()` | 聚类撤回全系统同步 | `MultiClusteringManager.unskip_char()` |
| `batch_skip_prelabels(sync_downstream)` | 批量跳过预标注，`sync_downstream=False` 时仅更新 prelabel_status + label_history | `_sync_skip_to_all()`（False）、预标注页面（True） |

### 8.4 跨轮次同步机制

> **重要**：同一字符可能存在于多个轮次的聚类中。同步方法必须遍历所有轮次，确保每个包含该字符的聚类标注都被更新。

| 方法 | 遍历行为 | 文件写入优化 |
|------|----------|-------------|
| `_sync_to_multi_clustering()` | 遍历所有 `round_N/` 目录，查找包含该 `char_id` 的聚类 | 每轮次仅在有变更时保存一次 `labels.json` |
| `_sync_skip_to_multi_clustering()` | 同上 | 同上 |
| `_sync_reset_to_multi_clustering()` | 同上 | 同上 |

#### 历史问题

| 问题 | 根因 | 修复 |
|------|------|------|
| 预标注确认后，多轮聚类页面无汉字显示 | `_sync_to_multi_clustering` 找到第一个匹配后 `return`，未继续更新其他轮次 | 改为遍历所有轮次，用 `round_found` 标记，每轮结束后统一保存 |
| 写入路径错误 | 使用 `round_dir / "labeling" / "labels.json"` 而非 `round_dir / "labels.json"` | 修正为 `round_dir / "labels.json"` |
| 已有标签无法修改 | `_validate_update` 在字符已有标签且新标签不同时 `raise ValueError` | 改为覆盖模式，`_validate_update` 始终返回 `True`，记录覆盖日志 |
| 跳过操作双重同步 | Manager 的 `_sync_skip_to_all` 调用 `batch_skip_prelabels`，后者内部已同步下游，Manager 又额外调用 `_update_unified_labels_status` | 给 `batch_skip_prelabels` 添加 `sync_downstream` 参数，Manager 调用时设为 `False`，由 Manager 统一调度同步 |
| 跳过操作缺少 round labels 同步 | `_sync_skip_to_all` 未显式同步 `round_N/labels.json` | 新增步骤 5：调用 `_sync_skip_to_multi_clustering` 显式同步多轮聚类 |
| 撤回跳过缺少 round labels 同步 | `_sync_unskip_to_all` 未同步 `round_N/labels.json` | 新增步骤 5：调用 `_sync_reset_to_multi_clustering` 显式同步多轮聚类 |
| 跳过后 labeled.json 未清理 | `_sync_to_char_pool_skipped` 和 `CharPoolManager.mark_as_skipped` 未从 `labeled.json` 移除 | 两个方法均新增从 `labeled.json` 移除的逻辑 |
| revoke_annotation 调用空方法 | `_remove_from_multi_clustering` 是空方法，与 `_sync_reset_to_multi_clustering` 功能重叠 | 删除空方法调用，保留已实现的 `_sync_reset_to_multi_clustering` |
| 数据结构错误 | 直接操作 `labels` 顶层字典，但文件结构为 `{"labels": {cluster_id: {...}}}` | 改为 `labels_data["labels"]` 操作后保存 `labels_data` |
| 右键上下文显示位置错误 | 聚类结果中 `col_start`/`col_end` 为 0，前端使用 `charIndex * 60` 估算坐标 | 后端从 `all_chars.json`（lineage）补充缺失坐标；前端移除估算逻辑，坐标为 0 时报错提示 |

### 9.3 数据源约束

| 约束项 | 规则 |
|--------|------|
| 坐标数据源 | 必须来源于 `all_chars.json`（源自 `lineage.json`），**禁止估算** |
| line_name 兜底 | 仅当 `all_chars.json` 中也为空时，允许从 `char_id` 正则提取 |
| 坐标缺失处理 | `col_start` 或 `col_end` 为 0 时，**不得显示上下文**，报错提示 |
| 跨页面一致性 | 同一图片在预标注页面和多轮聚类页面必须显示相同的上下文 |
