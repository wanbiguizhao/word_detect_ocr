# 多轮聚类数据源扩展 — 方案评估

## 1. 当前架构回顾

### 1.1 聚类输入数据流（现状）

```
pre_labels.json (OCR 预测, ~4.3MB 只读)
    ├── confidence, confidence_level, predicted_char
    └── → prelabel_status.json (.meta/ 可写, 存 status + corrected_char)
              ↓
unified_labels.json (标注数据, status="labeled")
    ↓
DataStore.get_confirmed_annotations()
    ↓
CharPool._get_existing_labeled_chars()   ← 初始化时排除已标注字符
    ↓
CharPool.get_unlabeled_char_ids()        ← 每次聚类取未被标注的 char_id
    ↓
MultiClusteringManager.start_new_round()
    ├── 为每个 char_id 加载图片 → 提取 HOG 特征 (1764维)
    ├── HDBSCAN(KMeans) 聚类
    ├── 拆分超大类
    └── 聚类内相似度排序
```

**关键约束**：当前聚类**只处理未标注字符**（通过 CharPool 过滤）。置信度信息（来自 `pre_labels.json`）完全不参与聚类输入筛选。

### 1.2 当前前端参数面板

```vue
<!-- MultiClusteringPage.vue -->
<a-select v-model:value="method">   HDBSCAN / KMeans
min_cluster_size: 3-50             (仅 HDBSCAN)
min_samples: 1-20                  (仅 HDBSCAN)
max_cluster_size: 10-200           (仅 HDBSCAN)
n_clusters: 2-100                  (仅 KMeans)
```

## 2. 三种新数据源模式

### 2.1 模式一：未标注汉字（现有逻辑显式化）

**触发条件**：`data_source = "unlabeled"`

**数据流**：

```
CharPool.get_unlabeled_char_ids()
    ↓
提取 HOG 特征 → 聚类
```

**与现状的关系**：和当前行为完全一致，只需显式化参数。**后端不需要任何改动**，仅前端增加一个数据源选择器，默认选中此项。

**前端参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `data_source` | select | `"unlabeled"` |
| 聚类方法及参数 | 同上 | HDBSCAN/KMeans + 现有参数 |

**优势**：
- 零后端开发量
- 行为完全可预测

**局限**：
- 无法利用置信度信息
- 无法对已标注数据做质量审查

---

### 2.2 模式二：低置信度数据聚类

**触发条件**：`data_source = "low_confidence"` + `confidence_threshold`

**核心思路**：OCR 对某些图片预测不太确定（置信度 < 0.7），这些"拿不准"的图片容易出错，值得单独拎出来做一轮聚类审查。

**数据流**：

```
pre_labels.json (全部预标注数据)
    ↓
过滤: confidence < confidence_threshold   (用户可调，默认 0.7)
    ↓
过滤: status != "confirmed"               (排除已确认的)
    ↓
得到候选 char_id 列表
    ↓
提取 HOG 特征 → 聚类
```

**后端改造点**：

1. **新增方法** `MultiClusteringManager.start_new_round()` 增加 `data_source` 和 `confidence_threshold` 参数
2. **新增方法** `DataStore.get_low_confidence_char_ids(threshold)` 或复用现有 `pre_labels.json` 加载逻辑
   - 遍历 `_prelabels_list`，筛选 `confidence < threshold`
   - 交叉检查 `_prelabel_status` 排除 `status == "confirmed"`
   - 返回 `List[str]`（char_id 列表）
3. **CharPool 逻辑保持不变**：模式二不受 CharPool 管理（CharPool 只追踪 labeled/unlabeled，不知道 confidence）

**依赖关系**：

```
DataStore._prelabels_list (内存中已加载)
    ↓ 读取 confidence 字段
    ↓ 交叉 prelabel_status 排除 confirmed
    ↓
返回 char_id 列表 → 聚类管道
```

**需要确认的前置条件**：

| 条件 | 当前状态 | 是否满足 |
|------|---------|---------|
| `pre_labels.json` 存在 | `pdf5826` 目录中有，~4.3MB | ✅ |
| 内存中已加载 | `DataStore._preload_indexes()` 已加载 | ✅ |
| confidence 字段格式 | `float, 0.0~1.0` | ✅ |
| 状态交叉查询可行 | `prelabel_status.json` 独立存储 | ✅ |

**前端参数**：

| 参数 | 类型 | 说明 | 默认值 |
|------|------|------|--------|
| `data_source` | select | `"low_confidence"` | — |
| `confidence_threshold` | slider/number | 只聚类置信度低于此值的图片 | `0.7` |
| 聚类方法及参数 | 同上 | HDBSCAN/KMeans | — |

**潜在问题与风险**：

- ⚠️ **数据量可能很大**：低置信度图片可能几千张，HDBSCAN 预计算余弦距离矩阵需要 O(n²) 内存。如果 n=5000，距离矩阵约 5000×5000×8 = 200MB。需考虑：
  - 限制最大输入数量（如 2000 张，截断或随机采样）
  - 或使用增量/分批聚类
- ⚠️ **`DataStore` 仅管理当前数据集**：`_prelabels_list` 只包含当前 dataset_id 的数据，数据隔离已保证
- ⚠️ **和 CharPool 的联系**：低置信度聚类不修改 CharPool 状态，CharPool 只追踪"是否被标注"，不追踪"是否被低置信度聚类过"

### 2.3 模式三：已标注数据的离群点检测

**触发条件**：`data_source = "outlier"` + `outlier_threshold`

**核心思路**：用户已经标注了大量汉字（如"的"标了 773 张），但其中可能混入了标注错误。离群点检测的目标是：**在同一个标注汉字的所有图片中，找出"长得不像其他图片"的那几张**。

**算法选择**：

#### 方案 A：余弦距离离群分（推荐）

对每个已标注汉字 `char`：
1. 收集所有 status="labeled" 且 char=该字 的图片
2. 提取 HOG 特征
3. 对每组汉字分别计算：
   - 计算组内特征向量的**质心** (centroid)
   - 计算每张图片到质心的**余弦距离**
   - 按距离降序排列，返回 Top-K 离群点（K 由用户指定或自动判定：距离 > 均值 + 2×标准差）

**优点**：
- 简单，可解释性强
- 计算量可控（每组独立计算，可并行）
- 每个汉字独立做，不会跨汉字混淆

**缺点**：
- 如果组内本身方差很大（如"中"字有多种写法），离群点可能并不真的"错"

#### 方案 B：LOF (Local Outlier Factor)

使用 sklearn 的 `LocalOutlierFactor`，对每组汉字独立计算。

**优点**：考虑局部密度，对非球形分布更鲁棒

**缺点**：计算量大，参数调优困难，可解释性差

#### 方案 C：最近邻相似度分

对每个已标注汉字 `char`：
1. 收集所有该字的图片特征
2. 对每张图片，找其最近邻（组内）的余弦相似度
3. 最近邻相似度最低的即为离群点

**优点**：最直观——"这张图和组里最近的图都不像"
**缺点**：只考虑 pairwise，不考虑整体结构

**推荐方案 A**（余弦距离离群分），作为默认，后续可扩展为方案 C。

**数据流**：

```
unified_labels.json (全部已标注)
    ↓
按 char 分组: {"的": [773张], "。": [500张], ...}
    ↓
对每组:
    1. 加载所有图片 → 提取 HOG 特征
    2. 计算质心 → 计算每张图到质心的余弦距离
    3. 排序 → 返回 Top-K 离群点
    ↓
聚合所有组的离群点，按离群分数降序排列
    ↓
可选：再将离群点做一轮聚类，把"错标成同一个错误字"的图片聚在一起
```

**后端改造点**：

1. **新模块或新方法** `MultiClusteringManager.detect_outliers(data_source, params)`
   - 输入：`data_source = "outlier"`, `outlier_top_k` 或 `outlier_std_multiplier`
   - 输出：离群点列表（含 char_id, labeled_char, outlier_score, 图片路径）
2. **数据获取**：调用 `DataStore.get_confirmed_annotations()` 或直接读 `unified_labels.json`
3. **特征提取**：复用现有 `_extract_hog_features()`
4. **离群检测**：新增 `_compute_outlier_scores(features)` 方法

**前端参数**：

| 参数 | 类型 | 说明 | 默认值 |
|------|------|------|--------|
| `data_source` | select | `"outlier"` | — |
| `outlier_method` | select | `"centroid"` / `"nearest_neighbor"` | `"centroid"` |
| `outlier_top_k` | number | 每组返回几个离群点 | `5` |
| `outlier_std_multiplier` | number | 标准差倍数阈值 | `2.0` |
| 后置聚类 | toggle | 是否对离群点再做一次聚类 | `true` |

**潜在问题与风险**：

- ⚠️ **数据量**：`unified_labels.json` 全局文件有 25,812 条标注。若全部加载做离群检测：
  - 需要加载 25,812 张图片 → 提取 25,812 个 1764 维特征 → 约 350MB 内存
  - 按 char 分组后，大组（"的"773张）质心计算很快，但图片 I/O 是瓶颈
  - **必须限制数据集范围**（只检测当前 dataset 的数据）
- ⚠️ **结果展示**：离群点检测的输出格式和现有聚类不同——现有是"一个 cluster 内多张图"，离群是"退回单个图片 + 分数"。前端需要新 UI 或者复用现有聚类卡片样式
- ⚠️ **阈值敏感性**：`outlier_std_multiplier = 2.0` 对不同汉字效果差异大。有些汉字形态单一（如"一"），2σ 可能过滤掉很少；有些汉字形态多样（如"的"），2σ 可能过滤掉很多正常变体
- ⚠️ **冷启动问题**：如果某个汉字只有 1-2 张标注，离群检测无意义（样本太少）。需要 **min_group_size** 参数（默认 5）

```python
def start_new_round(self, data_source="unlabeled", confidence_threshold=0.7, ...):
    if data_source == "unlabeled":
        char_ids = self.char_pool.get_unlabeled_char_ids()
    
    elif data_source == "low_confidence":
        # 1. 获取低置信度 char_id
        prelabels = self.data_store.get_all_prelabels()  # 新增方法
        char_ids = [
            p["char_id"] for p in prelabels
            if p["confidence"] < confidence_threshold
        ]
        # 2. 排除已确认的
        confirmed = self.data_store.get_confirmed_char_ids()  # 新增方法
        char_ids = [c for c in char_ids if c not in confirmed]
        # 3. 限制数量
        if len(char_ids) > MAX_INPUT:
            char_ids = random.sample(char_ids, MAX_INPUT)
    
    elif data_source == "outlier":
        return self._run_outlier_detection(...)
    
    # 后续聚类管道（复用现有逻辑）
    features = [self._extract_hog_features(id_to_path[c]) for c in char_ids]
    labels = self._run_clustering(features, method, params)
    ...
```

### 4.3 模式三后端伪代码

```python
def _run_outlier_detection(self, outlier_method, outlier_top_k, ...):
    # 1. 获取当前数据集的所有已标注
    confirmed = self.data_store.get_confirmed_annotations()
    # {char_id: char, ...}
    
    # 2. 按 char 分组
    groups = defaultdict(list)
    for char_id, char in confirmed.items():
        groups[char].append(char_id)
    
    # 3. 过滤小组
    groups = {k: v for k, v in groups.items() if len(v) >= min_group_size}
    
    # 4. 对每组计算离群分
    all_outliers = []
    for char, char_ids in groups.items():
        features = [self._extract_hog_features(id_to_path[c]) for c in char_ids]
        if outlier_method == "centroid":
            scores = self._outlier_by_centroid(features)
        elif outlier_method == "nearest_neighbor":
            scores = self._outlier_by_nn(features)
        
        # 取Top-K 或 超过阈值
        for i in np.argsort(scores)[-outlier_top_k:]:
            if scores[i] > threshold:
                all_outliers.append({
                    "char_id": char_ids[i],
                    "labeled_char": char,
                    "outlier_score": scores[i],
                    "image_path": ...
                })
    
    # 5. 可选：对离群点再做聚类
    if post_cluster:
        ...  # 复用现有聚类管道
    
    # 6. 保存为特殊轮次
    ...
```

## 5. 关键风险与权衡

### 5.1 模式二：数据量大

| 数据集 | pre_labels.json 条目数 | 低置信度(<0.7) 大约多少 | 内存估算 |
|--------|----------------------|----------------------|----------|
| pdf5826 | ~6000 | ~1200 (20%) | 距离矩阵 ~11MB |
| pdf01 | ~24000 | ~4800 (20%) | 距离矩阵 ~180MB ⚠️ |

**对策**：
- 默认 `max_input = 2000`，超出时随机采样
- 前端提示"共 X 张低置信度图片，已随机采样 2000 张"
- 后续可考虑分批聚类 + 合并结果

### 5.2 模式三：图片I/O 是瓶颈

- 25,812 张图片（全局）或 ~6000 张（单数据集）
- 每张图片读取 + HOG 提取约 5-10ms → 6000 张需 30-60 秒
- 需要**进度反馈**（WebSocket 或轮询）
- 建议首次只检测当前数据集（`dataset_id` 过滤）

### 5.3 结果格式不统一

- 模式一/二：输出格式和现有聚类完全一致（`rounds/round_N/hog_clusters.json`），前端不需要改动
- 模式三：输出的是"离群点列表"，和现有聚类格式不同。**需要在 `round_history.json` 中标记轮次类型**，前端按类型渲染不同 UI

### 5.4 轮次类型标记

建议在 `round_history.json` 中增加字段：

```json
{
    "round_id": 20,
    "type": "outlier",         // "clustering" | "outlier"
    "data_source": "outlier",
    "params": { ... },
    "created_at": "..."
}
```

前端根据 `type` 决定列表页显示为"第N轮聚类"还是"离群检测报告"。

## 7. 总结

三个数据源覆盖了 OCR 标注工作流的三个关键场景：

| 模式 | 场景 | 价值 |
|------|------|------|
| 未标注汉字 | 发现新汉字、扩展现有标注覆盖 | 当前行为，保证向后兼容 |
| 低置信度 | 优先审查 OCR 不确定的图片，提高整体准确率 | **高价值**：精准打击易错点 |
| 离群检测 | 审查已标注数据中可能的标注错误 | **高价值**：质量控制，查漏补缺 |

**建议先从 Phase 1 + Phase 2 开始**，模式一零风险、模式二改动可控。模式三需要更多设计和前端适配，值得单独迭代。
