# 预标注确认页面 - 需求规格说明书

## 1. 页面概述

| 属性 | 值 |
|------|-----|
| **路由** | `/prelabel-confirm/:char` |
| **用途** | 对 OCR 预标注结果进行确认、修正、跳过操作 |
| **数据来源** | OCR 预测结果（pre_labels.json + prelabel_status.json） |
| **核心组件** | `PreLabelConfirmPage.vue` |
| **后端接口** | `/api/labeling/prelabels/:char` |

### 6.2 框选

## 7. 批量操作

### 7.1 批量确认

- 接口：`POST /api/labeling/confirm/batch`
- 请求体：`{ items: [{ char_id, char }] }`
- 排除已确认的项，仅确认非 confirmed 状态的项
- 确认后状态变为 `confirmed`
- 提示：排除 N 个已确认项，确认剩余 M 个

### 7.2 批量跳过

- 接口：`POST /api/labeling/skip/batch`
- 请求体：`{ char_ids: [...] }`
- 排除已跳过的项
- 跳过后状态变为 `skipped`

### 7.3 批量撤回

- 接口：`POST /api/labeling/revoke/batch`
- 请求体：`{ char_ids: [...] }`
- 仅撤回 confirmed 或 skipped 状态的项
- 撤回后状态变为 `pending`

### 7.4 取消跳过

- 接口：`POST /api/labeling/unskip/batch`
- 请求体：`{ char_ids: [...] }`
- 仅取消 skipped 状态的项
- 取消后状态变为 `pending`

### 7.5 批量修改

- 接口：`POST /api/labeling/modify/batch`
- 请求体：`{ char_ids: [...], new_char: "汉字" }`
- 修改后 `corrected_char` 更新，状态变为 `confirmed`
- 支持回车键触发

## 9. 排序逻辑

排序优先级（从高到低）：

1. **显示优先级**：待确认(0) > 已修正(1) > 预测正确(2)
2. **分组索引**：按显示字符分组，组内按数量升序
3. **置信度**：组内按置信度升序

## 11. 数据一致性

### 11.1 操作同步范围

| 操作 | pre_labels.json | prelabel_status.json | unified_labels.json | char_pool | round labels (多轮聚类) |
|------|-----------------|---------------------|---------------------|-----------|------------------------|
| 确认 | status → confirmed | status → confirmed | status → confirmed | labeled + labeled.json 添加 | ✅ 遍历所有轮次同步 |
| 跳过 | status → skipped | status → skipped | status → skipped | skipped + labeled.json 移除 | ✅ 遍历所有轮次同步 |
| 撤回 | status → pending | status → pending | status → pending | unlabeled + labeled.json 移除 | ✅ 遍历所有轮次同步 |
| 修改 | corrected_char + confirmed | corrected_char + confirmed | char 更新 | labeled + labeled.json 添加 | ✅ 遍历所有轮次同步 |

> **标注覆盖**：同一字符允许修改已有标签（覆盖模式）。`_validate_update` 不再阻止标签变更，而是记录覆盖日志。

### 11.2 跨轮次同步机制

> **重要**：同一字符可能存在于多个轮次的聚类中。预标注操作触发同步时，同步方法遍历所有轮次，确保每个包含该字符的聚类标注都被更新。

| 同步方法 | 功能 | 遍历行为 |
|----------|------|----------|
| `_sync_to_multi_clustering()` | 同步标注到多轮聚类 | 遍历所有 `round_N/` 目录，更新包含该 `char_id` 的聚类 |
| `_sync_skip_to_multi_clustering()` | 同步跳过到多轮聚类 | 同上 |
| `_sync_reset_to_multi_clustering()` | 同步重置到多轮聚类 | 同上 |

文件写入优化：每个轮次仅在有变更时保存一次 `labels.json`，避免重复 I/O。

### 11.3 历史问题与修复

| 问题 | 根因 | 修复 |
|------|------|------|
| 预标注确认后，多轮聚类页面无汉字显示 | `_sync_to_multi_clustering` 找到第一个匹配后 `return`，未继续更新其他轮次 | 改为遍历所有轮次，用 `round_found` 标记，每轮结束后统一保存 |
| 写入路径错误 | 使用 `round_dir / "labeling" / "labels.json"` 而非 `round_dir / "labels.json"` | 修正为 `round_dir / "labels.json"` |
| 数据结构错误 | 直接操作 `labels` 顶层字典，但文件结构为 `{"labels": {cluster_id: {...}}}` | 改为 `labels_data["labels"]` 操作后保存 `labels_data` |
| 已有标签无法修改 | `_validate_update` 在字符已有标签且新标签不同时 `raise ValueError` | 改为覆盖模式，`_validate_update` 始终返回 `True`，记录覆盖日志 |
| 跳过后 labeled.json 未清理 | `_sync_to_char_pool_skipped` 未从 `labeled.json` 移除 | 新增从 `labeled.json` 移除的逻辑 |
| 撤回后 labeled.json 未清理 | `_sync_to_char_pool_reset` 未从 `labeled.json` 移除 | 新增从 `labeled.json` 移除的逻辑 |
| revoke_annotation 调用空方法 | `_remove_from_multi_clustering` 是空方法，与 `_sync_reset_to_multi_clustering` 功能重叠 | 删除空方法调用，保留已实现的 `_sync_reset_to_multi_clustering` |
