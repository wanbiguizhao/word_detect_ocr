# 新汉字快速发现流程方案

## 1. 问题分析

### 1.1 当前流程

```
PDF → 切割(行/字) → OCR预测 → 预标注 → 人工确认/聚类标注 → 新汉字入库
```

**具体步骤**：
1. 逐个处理PDF文件，通过 `SegmentManager` 执行 PDF→图片→行→汉字 的切割
2. 使用 OCR 模型对切割出的汉字图片进行批量预测，生成 `pre_labels.json`
3. 通过预标注确认页面或多轮聚类页面进行人工标注
4. 标注结果写入 `unified_labels.json`，同步到字符池

### 1.2 当前数据规模

| 指标 | 数值 |
|------|------|
| 已标注图片总数 | 27,172 |
| 已标注不同汉字数 | ~1,300 |
| 数据集 | pdf01(23,711) + pdf5823(2,101) + pdf5826(1,360) |
| GB2312一级汉字 | 3,755 |
| GB2312二级汉字 | 3,008 |
| GB2312总计 | 6,763 |

**核心问题**：已标注1,300个汉字，仅占GB2312的19%。剩余81%的汉字尚未被发现和标注，按当前速度推进太慢。

### 1.3 瓶颈定位

| 瓶颈 | 原因 | 影响 |
|------|------|------|
| **串行处理** | 一次只处理一个PDF | 数据积累慢 |
| **聚类噪声高** | HDBSCAN将80%数据标记为噪声（第5轮205个输入仅40个进入聚类） | 有效发现少 |
| **发现策略单一** | 仅依赖HOG特征聚类发现新字 | 遗漏大量潜在新字 |
| **标注→训练断裂** | 标注后需手动执行训练脚本，模型不更新 | 无法利用主动学习加速 |
| **特征表达能力弱** | HOG是手工特征，对形近字区分力差 | 聚类质量低 |
| **数据源单一** | 仅使用当前数据集的未标注数据 | 无法跨数据集发现 |

## 3. 六大模块详细设计

### 3.1 模块一：批量并行预处理

**目标**：同时处理多个PDF，快速积累字符图片和OCR预测结果。

**当前问题**：`SegmentManager.process_pdf()` 是串行执行，一次只处理一个PDF。

**改进方案**：

```python
def batch_process_pdfs(pdf_dir, max_workers=4):
    """并行处理目录下所有PDF"""
    pdf_files = list(Path(pdf_dir).glob("*.pdf"))
    
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        futures = {}
        for pdf_path in pdf_files:
            dataset_id = pdf_path.stem  # 如 pdf5826
            future = executor.submit(process_single_pdf, pdf_path, dataset_id)
            futures[future] = dataset_id
        
        for future in as_completed(futures):
            dataset_id = futures[future]
            try:
                result = future.result()
                print(f"[OK] {dataset_id}: {result['total_chars']} chars")
            except Exception as e:
                print(f"[ERR] {dataset_id}: {e}")
```

**关键设计**：
- 每个PDF独立目录，数据隔离
- 处理完成后自动触发OCR预测（模块二的输入）
- 支持断点续处理（跳过已处理的PDF）

**输出**：
```
bussiness/datahome/{dataset_id}/
├── pdf_images/       # 页面图片
├── pdf_lines/        # 行图片
├── pdf_chars/        # 汉字图片
├── lineage.json      # 血缘关系
└── pre_labels.json   # OCR预测结果（模块二产出）
```

### 3.2 模块二：智能数据筛选

**目标**：从海量未标注数据中，按优先级筛选出最可能包含新汉字的数据。

**筛选策略**：

| 优先级 | 筛选条件 | 逻辑 | 预期命中率 |
|--------|----------|------|-----------|
| **P0** | 置信度 < 0.3 且预测字不在字符池 | OCR完全不确定 + 可能是新字 | 高 |
| **P1** | 置信度 0.3-0.5 且预测字出现频次 < 3 | OCR不太确定 + 稀有字 | 中高 |
| **P2** | 置信度 0.5-0.7 且未标注 | 中等不确定 | 中 |
| **P3** | 置信度 < 0.7 且预测字在字符池中仅1-2张 | 可能是标注错误或新字 | 中 |

**实现**：

```python
def smart_filter(dataset_id, char_pool, top_k=500):
    """智能筛选高价值未标注数据"""
    prelabels = load_prelabels(dataset_id)
    labeled_ids = char_pool.get_labeled_char_ids()
    char_distribution = char_pool.get_char_distribution()
    
    candidates = []
    for p in prelabels:
        char_id = p["char_id"]
        if char_id in labeled_ids:
            continue
        
        confidence = p["confidence"]
        predicted_char = p["predicted_char"]
        char_count = char_distribution.get(predicted_char, 0)
        
        # 计算优先级分数
        score = 0
        if confidence < 0.3 and char_count == 0:
            score = 100  # P0: 极可能新字
        elif confidence < 0.5 and char_count < 3:
            score = 80   # P1: 稀有字
        elif confidence < 0.7:
            score = 50   # P2: 不确定
        elif char_count <= 2:
            score = 30   # P3: 低频字
        
        if score > 0:
            candidates.append((score, p))
    
    candidates.sort(key=lambda x: x[0], reverse=True)
    return [p for _, p in candidates[:top_k]]
```

### 3.3 模块三：多策略新字发现

**目标**：用多种策略从筛选后的数据中发现新汉字，不依赖单一聚类方法。

#### 策略A：模型特征聚类（替代HOG）

**核心改进**：用OCR模型自身的特征（ResNet倒数第二层）替代HOG特征进行聚类。

**原理**：OCR模型在训练过程中学到了汉字的语义特征，同一汉字的图片在特征空间中距离更近。HOG是手工特征，只捕捉梯度方向，对形近字区分力差。

```
当前：汉字图片 → HOG特征(1764维) → HDBSCAN聚类 → 噪声80%
改进：汉字图片 → ResNet特征(1024维) → HDBSCAN聚类 → 预期噪声<30%
```

**实现**：

```python
def extract_model_features(image_paths, model, transform):
    """使用OCR模型提取特征（倒数第二层）"""
    # 移除最后的全连接层
    feature_extractor = nn.Sequential(*list(model.resnet.children())[:-1])
    feature_extractor.eval()
    
    features = []
    with torch.no_grad():
        for path in image_paths:
            img = Image.open(path).convert('L')
            img = transform(img).unsqueeze(0)
            feat = feature_extractor(img)
            features.append(feat.squeeze().numpy())
    
    return np.array(features)
```

**优势**：
- 特征表达能力远强于HOG
- 同字图片在特征空间中更紧凑
- 聚类噪声率大幅降低
- 复用已有模型，零额外训练成本

#### 策略B：预测一致性分析

**核心思路**：对同一聚类簇内的图片，如果OCR预测结果不一致，说明簇内可能混入了不同汉字，或者包含模型未见过的字。

```python
def analyze_prediction_consistency(cluster_chars, prelabels):
    """分析聚类簇内的预测一致性"""
    results = []
    for cluster_id, char_ids in cluster_chars.items():
        predictions = {}
        for char_id in char_ids:
            pred = get_prediction(char_id, prelabels)
            predictions[pred] = predictions.get(pred, 0) + 1
        
        # 一致性分数：最多预测字占比
        max_count = max(predictions.values())
        consistency = max_count / len(char_ids)
        
        if consistency < 0.5:
            # 低一致性：可能包含新字或标注错误
            results.append({
                "cluster_id": cluster_id,
                "consistency": consistency,
                "predictions": predictions,
                "priority": "high"
            })
    
    return results
```

#### 策略C：跨数据集对比发现

**核心思路**：在数据集A中已标注的汉字，在数据集B中可能以低置信度出现。通过跨数据集对比，可以快速发现新数据集中的未知字。

```python
def cross_dataset_discovery(source_datasets, target_dataset):
    """跨数据集发现新字"""
    # 收集所有已知汉字
    known_chars = set()
    for ds in source_datasets:
        distribution = load_char_distribution(ds)
        known_chars.update(distribution.keys())
    
    # 在目标数据集中查找低置信度 + 不在已知集合中的预测
    target_prelabels = load_prelabels(target_dataset)
    new_char_candidates = []
    
    for p in target_prelabels:
        if p["confidence"] < 0.5 and p["predicted_char"] not in known_chars:
            new_char_candidates.append(p)
    
    return new_char_candidates
```

#### 策略D：频度异常检测

**核心思路**：在中文文本中，汉字出现频率遵循Zipf定律。如果某个OCR预测字出现频率异常低（仅1-2次），可能是误识别，实际可能是另一个字。

```python
def detect_frequency_anomaly(prelabels, char_distribution):
    """检测频度异常的预测"""
    anomalies = []
    for p in prelabels:
        if p["confidence"] < 0.7:
            predicted = p["predicted_char"]
            freq = char_distribution.get(predicted, 0)
            if freq <= 2:
                anomalies.append({
                    "char_id": p["char_id"],
                    "predicted": predicted,
                    "confidence": p["confidence"],
                    "frequency": freq,
                    "reason": "low_freq_low_conf"
                })
    return anomalies
```

```python
def recommend_label(cluster_id, prelabels, char_distribution):
    """推荐聚类簇最可能的汉字标签"""
    char_ids = get_cluster_chars(cluster_id)
    
    # 方法1：OCR预测投票
    vote_counts = {}
    for char_id in char_ids:
        pred = get_prediction(char_id, prelabels)
        conf = get_confidence(char_id, prelabels)
        vote_counts[pred] = vote_counts.get(pred, 0) + conf
    
    # 方法2：上下文推断（利用lineage中的行信息）
    context_chars = get_context_chars(char_ids)
    
    # 综合推荐
    recommendations = sorted(vote_counts.items(), key=lambda x: x[1], reverse=True)
    return recommendations[:3]  # 返回Top3推荐
```

### 3.5 模块五：数据回流

**目标**：标注完成后，自动将新标注数据加入训练集，无需手动操作。

**当前问题**：标注完成后需要手动执行 `generate_train_csv_aug.py` → `train.py`，流程断裂。

**改进方案**：

```
标注完成 → 自动触发数据回流管道：
    1. 更新 unified_labels.json（已有）
    2. 更新字符池状态（已有）
    3. 更新字符映射 char_to_label.json（需新增）
    4. 重新生成训练CSV（需自动化）
    5. 触发增量训练（需新增）
```

**关键实现**：

```python
class DataReflowPipeline:
    """数据回流管道"""
    
    def on_annotation_complete(self, char_id, char, dataset_id):
        """标注完成回调"""
        # 1. 更新统一标注（已有）
        self.data_store.write_annotation(char_id, char)
        
        # 2. 更新字符映射（新增）
        self.update_char_mapping(char)
        
        # 3. 检查是否需要训练
        new_chars_count = self.count_new_chars_since_last_train()
        if new_chars_count >= self.train_threshold:  # 如每新增50个字触发一次
            self.trigger_incremental_training()
    
    def update_char_mapping(self, new_char):
        """更新字符映射，添加新汉字"""
        from ocr_system.configs.char_mapping import CharMappingManager
        manager = CharMappingManager()
        if not manager.char_exists(new_char):
            manager.add_custom_char(new_char)
            manager.save()
    
    def trigger_incremental_training(self):
        """触发增量训练"""
        # 1. 重新生成训练CSV
        from ocr_system.scripts.generate_train_csv_aug import generate_csv_with_augmentation
        generate_csv_with_augmentation(min_samples=20)
        
        # 2. 启动训练（异步）
        import subprocess
        subprocess.Popen([
            sys.executable, "ocr_system/train.py"
        ])
```

### 3.6 模块六：模型增量更新

**目标**：标注数据积累到一定量后自动训练，用更好的模型重新预测，形成闭环。

**当前问题**：模型训练是手动触发的，训练后需要手动复制模型文件、手动重新预测。

**改进方案**：

```
增量训练流程：
    1. 检测新增标注数量
    2. 新增 >= N个字 或 >= M条标注 时自动触发
    3. 执行训练（支持断点续训）
    4. 验证新模型准确率
    5. 准确率提升 → 替换推理模型
    6. 用新模型重新预测所有未标注数据
    7. 更新 pre_labels.json
    8. 回到模块二，重新筛选
```

**训练策略**：

| 场景 | 策略 | 说明 |
|------|------|------|
| 新增少量字（< 50） | 冻结backbone，只训练FC层 | 快速，5-10分钟 |
| 新增大量字（>= 50） | 全模型微调 | 较慢，30-60分钟 |
| 新增大量数据 | 全模型训练 | 慢，1-2小时 |

**模型验证**：

```python
def validate_new_model(new_model_path, old_model_path, val_csv):
    """验证新模型是否优于旧模型"""
    old_acc = evaluate_model(old_model_path, val_csv)
    new_acc = evaluate_model(new_model_path, val_csv)
    
    if new_acc > old_acc:
        # 替换推理模型
        shutil.copy(new_model_path, INFERENCE_MODEL_PATH)
        return True
    return False
```

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 模型特征聚类内存不足 | 大数据集OOM | 限制单次聚类数量（max_input=2000），分批聚类 |
| 增量训练导致灾难性遗忘 | 旧字准确率下降 | 使用知识蒸馏保留旧模型能力；验证集包含旧字 |
| 自动训练占用GPU | 影响其他任务 | 夜间自动训练；支持CPU训练模式 |
| 错误标注回流训练 | 模型学错 | 离群检测（模式三）审查已标注数据；训练前验证 |
| 跨数据集字符ID冲突 | 数据混乱 | 字符ID包含数据集前缀，天然隔离 |
