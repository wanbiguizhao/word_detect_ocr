# 预标注页面操作数据流图

## 1. 概述

本文档描述同一张图片在**预标注确认页面**（`/prelabel-confirm/:char`）执行操作后，数据在各系统间的流转情况，以及**多轮聚类页面**（`/mc-label/:round/:cluster_id`）看到的数据变化。

---

## 2. 涉及的数据存储

| 存储文件 | 路径 | 说明 |
|----------|------|------|
| pre_labels.json | `bussiness/datahome/{dataset}/pre_labels.json` | OCR 预测结果（predicted_char, confidence） |
| prelabel_status.json | `bussiness/datahome/{dataset}/prelabel_status.json` | 预标注状态（status, corrected_chars） |
| unified_labels.json | `bussiness/datahome/{dataset}/unified_labels.json` | 统一标注数据（char, status, source） |
| all_chars.json | `bussiness/datahome/{dataset}/multi_clustering/char_pool/all_chars.json` | 字符池（status, label, labeled_round） |
| unlabeled.json | `bussiness/datahome/{dataset}/multi_clustering/char_pool/unlabeled.json` | 未标注字符列表 |
| labeled.json | `bussiness/datahome/{dataset}/multi_clustering/char_pool/labeled.json` | 已标注字符列表 |
| round labels.json | `bussiness/datahome/{dataset}/multi_clustering/rounds/round_N/labels.json` | 多轮聚类标注（char_labels, status） |
| label_history.json | `bussiness/datahome/{dataset}/label_history.json` | 标注历史记录 |

---

## 3. 初始状态

假设图片 `page_1_line_3_char_5`，OCR 预测为"效"，置信度 0.85：

```
pre_labels.json:
  page_1_line_3_char_5 → { predicted_char: "效", confidence: 0.85 }

prelabel_status.json:
  status: { page_1_line_3_char_5: "pending" }
  corrected_chars: {}  (无修正)

unified_labels.json:
  annotations: []  (无记录)

all_chars.json:
  page_1_line_3_char_5 → { status: "unlabeled", label: null }

unlabeled.json:
  char_ids: ["page_1_line_3_char_5", ...]

labeled.json:
  char_ids: []

round labels.json:
  (无标注记录)
```

## 4. 操作一：确认（Confirm）

### 4.1 触发方式

- 单击确认按钮
- 批量确认（`POST /api/labeling/confirm/batch`）

### 4.2 调用链

```
前端 → POST /api/labeling/confirm/batch
     → StatsManager.batch_confirm_annotations()
     → DataStore.batch_write_annotations(annotations, source="ocr_confirm")
```

## 9. 数据一致性总结

### 9.1 操作同步矩阵

| 操作 | prelabel_status | unified_labels | all_chars (字符池) | unlabeled.json | labeled.json | round labels (聚类) |
|------|-----------------|----------------|--------------------|----------------|--------------|--------------------|
| 确认 | ✅ confirmed + corrected | ✅ labeled | ✅ labeled | ✅ 移除 | ✅ 添加 | ✅ labeled |
| 修改 | ✅ confirmed + corrected | ✅ labeled | ✅ labeled | ✅ 移除 | ✅ 添加 | ✅ labeled |
| 跳过 | ✅ skipped | ✅ skipped | ✅ skipped | ✅ 移除 | ✅ 移除 | ✅ skipped |
| 撤回确认 | ✅ pending | ✅ 删除记录 | ✅ unlabeled | ✅ 添加 | ✅ 移除 | ✅ unlabeled |
| 取消跳过 | ✅ pending | ✅ pending | ✅ unlabeled | ✅ 添加 | ✅ 移除 | ✅ unlabeled |

> **标注覆盖**：同一字符允许修改已有标签（覆盖模式）。`_validate_update` 不再阻止标签变更，而是记录覆盖日志。

### 9.2 同步方法说明

| 方法 | 功能 | 调用位置 |
|------|------|----------|
| `_sync_to_char_pool_labeled()` | 同步标注到字符池（all_chars + labeled.json添加 + unlabeled.json移除） | 确认、修改操作 |
| `_sync_to_char_pool_skipped()` | 同步跳过到字符池（all_chars + unlabeled.json移除 + labeled.json移除） | 跳过操作 |
| `_sync_to_char_pool_reset()` | 同步重置到字符池（恢复为 unlabeled + unlabeled.json添加 + labeled.json移除） | 撤回、取消跳过操作 |
| `_sync_to_multi_clustering()` | 同步标注到多轮聚类 round labels（**遍历所有轮次**） | 确认、修改操作 |
| `_sync_skip_to_multi_clustering()` | 同步跳过到多轮聚类 round labels（**遍历所有轮次**） | 跳过操作 |
| `_sync_reset_to_multi_clustering()` | 同步重置到多轮聚类 round labels（**遍历所有轮次**） | 撤回、取消跳过操作 |
| `correct_prelabel_char()` | 更新 corrected_chars 字段 | 确认操作（batch_write_annotations） |

### 9.3 双向一致性

| 方向 | 同步完整性 | 说明 |
|------|-----------|------|
| 预标注 → 多轮聚类 | ✅ 完整 | 确认/修改/跳过/撤回均全系统同步 |
| 多轮聚类 → 预标注 | ✅ 完整 | 标注/跳过/撤回均全系统同步 |

### 9.4 跨轮次同步机制

> **重要**：同一字符可能存在于多个轮次的聚类中。同步方法必须遍历所有轮次，确保每个包含该字符的聚类标注都被更新。

| 方法 | 遍历行为 | 文件写入优化 |
|------|----------|-------------|
| `_sync_to_multi_clustering()` | 遍历所有 `round_N/` 目录，查找包含该 `char_id` 的聚类 | 每轮次仅在有变更时保存一次 `labels.json` |
| `_sync_skip_to_multi_clustering()` | 同上 | 同上 |
| `_sync_reset_to_multi_clustering()` | 同上 | 同上 |

#### 历史问题

| 问题 | 根因 | 修复 |
|------|------|------|
| 预标注确认后，多轮聚类页面无汉字显示 | `_sync_to_multi_clustering` 找到第一个匹配后 `return`，未继续更新其他轮次 | 改为遍历所有轮次，用 `round_found` 标记，每轮结束后统一保存 |
| 写入路径错误 | 使用 `round_dir / "labeling" / "labels.json"` 而非 `round_dir / "labels.json"` | 修正为 `round_dir / "labels.json"` |
